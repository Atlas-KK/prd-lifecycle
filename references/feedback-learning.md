# PRD Lifecycle 反馈学习协议

本协议用于从用户明确反馈中改进 PRD 创建、补全、评审或执行规划，同时防止一次性业务决定被误写成长期规则。

## 学习层级

采用能够满足反馈的最窄层级：

1. **当前任务**：立即应用到当前 PRD 工作流，不写文件。
2. **当前项目**：用户明确要求“本项目以后这样”时，写入用户批准的项目规则文件。
3. **跨任务规则**：用户明确批准后，写入 `learned-guidance.md`。
4. **核心 Skill**：只有用户明确要求修改 Skill 定义时，才修改 `SKILL.md` 或其他流程参考。

一个层级的授权不代表更宽层级也获授权。

## 可学习内容

适合学习：澄清轮次、选择题数量、PRD 章节与措辞、版本节奏、用户故事粒度、MVP 划分、边界分类、验收深度、评审严重度校准、阶段粒度、追踪矩阵和报告结构。

不得学习：未经确认的推断、一次性业务规则、原始文档内容、源代码、账号、凭据、个人信息、商业秘密，或任何削弱事实核验、审阅门禁、版本管理和授权边界的规则。

## 强反馈信号

- 用户解释了某项推荐或评审结论为何错误。
- 用户指出遗漏的重大需求、风险或仓库约束。
- 相同流程偏好在独立决策中反复出现。
- 用户明确要求记住、推广、缩小、替换或撤销规则。
- 返工证明流程存在稳定缺陷，而非项目特例。

沉默、普通确认和一次性项目选择只影响当前任务，不足以持久化。

## 候选与批准

将可复用反馈压缩为一条候选规则，使用 `LC-YYYYMMDD-NN` 标识，并说明：反馈摘要、可执行规则、建议作用域、依据、收益、过拟合风险、影响模式和状态。

在自然检查点最多提出一项可选学习建议。写入前必须展示具体规则与作用域并获得明确确认；普通的“继续”“本步确认”不等于批准长期学习。

## 存储与优先级

- 项目规则仅写入用户批准的项目文件；未指定时建议 `<workspace>/.codex/skill-learning/prd-lifecycle.md`，不可写时先请求授权。
- 跨任务规则写入本 Skill 的 `references/learned-guidance.md`。
- 持久化后回读并运行 Skill 验证器。
- 保留被替换或撤销规则的审计记录，以 `retired` 或 `superseded` 标记，不静默删除。

优先级为：当前明确指令 > 当前任务已确认决定 > 适用项目规则 > 跨任务规则 > Skill 默认规则。
