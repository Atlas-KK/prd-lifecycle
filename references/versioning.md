# 版本管理规则（版本自增）

文档每次内容更新都要自增版本并记录修订历史，确保可追溯。

## 版本号规则
- 形式：`v主版本.次版本`，如 `v1.0`、`v1.3`、`v2.0`。
- **基线导入**：读入原始需求文档后，作为基线 = **v1.0**。
- **每个步骤确认后写入文档** = **次版本 +1**（v1.0→v1.1→v1.2…）。这是"每次内容更新版本自增"的常态触发点。
- **整稿合并 / 重大重构 / 交付定稿** = **主版本进位**，次版本归零（如 v1.4→v2.0）。
- 用户在某步要求修改、在本步内反复迭代时：**未确认前不bump**；只有"确认并写入"才bump一次。

## 何时 bump
| 事件 | 操作 |
|---|---|
| 导入原始文档 | 建基线 v1.0 |
| 某步产出经用户确认、写入对应章节 | minor +1 |
| 追加的扩展步骤经确认写入 | minor +1 |
| 四步走完、整稿合并为完整交付文档 | major 进位（→ vX.0） |
| 用户仅审阅未确认 / 仍在改本步 | 不bump |

## 版本历史表（置于文档顶部，最新在最上）
```
## 版本历史

| 版本 | 日期 | 阶段/步骤 | 修订内容 | 修订人 |
|---|---|---|---|---|
| v1.2 | 2025-06-01 | 步骤2 功能方案 | 补充功能方案设计章节 | 产品经理 |

> **当前版本：v1.2**
```

## 用脚本维护（推荐，避免手算/漏记）
见 `scripts/prd_doc.py`：
- `init`  建基线 v1.0 + 文档骨架；
- `bump`  读取当前版本→自增→在表首插入一行→更新"当前版本"标记；
- `export` 导出 .docx 交付稿。
手工维护时务必同时更新表格行与"当前版本"标记两处。
